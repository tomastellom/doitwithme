# Daily check-in Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Nudge asks once a day how the user is (Good, Okay, Low); a Low answer caps today's generated work at a user-set minimum and moves the rest to later days, with an undo.

**Architecture:** The answer is stored in `state.checkIns`. The planner reads the Low dates and caps generated minutes on them, so undo is just a new answer plus a replan. A small server module computes what moved. The browser store, a Nudge check-in state, two settings rows and a Day tag sit on top. No new dependencies.

**Tech Stack:** TypeScript run by Node's type stripping (`node --test`), plain ES module browser code, hand-rolled fake DOM in tests. Run all tests with `npm test`.

**Spec:** `docs/superpowers/specs/2026-10-11-check-in-design.md`

## Global Constraints

- No emojis, no gradients, no inline styles (CSP), all text through `createTextNode` (the `h()` helper does this), reduced motion respected.
- Fixed commitments (classes, lessons, work) never move on a Low day.
- Defaults: `lowDayMinutes` 120 (range 0 to 600, whole minutes), `checkInEnabled` true.
- `checkIns` older than 60 days are dropped on replan. One entry per date; a new answer replaces the old one.
- Old saved state without the new fields must load (defaults fill in).
- Do not push. The user pushes when they say yes.
- Commit trailer on every commit: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- Spec deviations decided while planning (the spec file is updated in Task 1): (a) the request carries the client clock `today` like every other endpoint, instead of a server clock; (b) "Low-day minimum" in Settings is a row of choices (1 h, 2 h, 3 h, 4 h) like the other rows, not a free number input. The server still accepts 0 to 600.

## Review Focus

- Answering Low when today already has ticked-done blocks: they count toward the cap and are never removed (Task 2).
- Answering Low late in the day (`nowMinutes` set): blocks already passed stay, and the cap applies to what is still to be placed (Task 2).
- A cap smaller than `minBlock` (for example 20 with `minBlock` 30) places nothing instead of a tiny block (Task 2).
- Low answered twice in a row, or Low then Okay: the second answer replaces the first and the plan is restored (Tasks 3, 6).
- A hostile or wrong `mood` or a missing `today` is a 400 and changes nothing (Task 3).
- Check-in switched off, or no blocks today: Nudge never asks (Task 5).

```ts
import { replan } from './replan.ts';
import type { Block, DateStr, Mood, State } from './types.ts';

export interface Moved {
  minutes: number;
  dates: DateStr[];
}

interface Clock {
  today: DateStr;
  nowMinutes?: number;
  horizonDays: number;
}

// Generated work only: ticked, skipped and passed blocks are not what a low day moves.
const generated = (blocks: Block[], date: DateStr): number =>
  blocks.filter((b) => b.date === date && b.status === undefined).reduce((t, b) => t + (b.end - b.start), 0);

export function applyCheckIn(state: State, mood: Mood, clock: Clock): { state: State; moved: Moved | null } {
  const answered: State = {
    ...state,
    checkIns: [...(state.checkIns ?? []).filter((c) => c.date !== clock.today), { date: clock.today, mood }],
  };
  const next = replan(answered, clock.today, clock.nowMinutes, clock.horizonDays).state;
  if (mood !== 'low') return { state: next, moved: null };
  const before = replan(state, clock.today, clock.nowMinutes, clock.horizonDays).state.blocks;
  const minutes = Math.max(0, generated(before, clock.today) - generated(next.blocks, clock.today));
  const dates = [...new Set(next.blocks.map((b) => b.date))]
    .filter((d) => d > clock.today && generated(next.blocks, d) > generated(before, d))
    .sort();
  return { state: next, moved: { minutes, dates: minutes > 0 ? dates : [] } };
}
```

import { FULL_WEEKDAYS, WEEKDAYS, duration, weekdayOf } from './time.js';

export const todayMood = (state, today) => {
  const found = state && (state.checkIns ?? []).find((c) => c.date === today);
  return found ? found.mood : null;
};

const hasBlocks = (state, today) => state.blocks.some((b) => b.date === today);

export const canReopen = (state, today) =>
  Boolean(state) && state.preferences.checkInEnabled && todayMood(state, today) === 'skipped';

export const shouldAsk = (state, today, reopened) =>
  Boolean(state) && state.preferences.checkInEnabled && hasBlocks(state, today)
    && (todayMood(state, today) === null || (reopened && todayMood(state, today) === 'skipped'));

// The wording is rule-based and picked by the date, so one day always reads the same.
const pick = (lines, date) => lines[Number(date.slice(8)) % lines.length];
const dayName = (date) => FULL_WEEKDAYS[weekdayOf(date)];

export const askLine = (date) => pick(['How are you today?', `How is ${dayName(date)} treating you?`, 'How are you feeling today?'], date);

const REPLIES = {
  good: ['Glad to hear it. The plan stays as it is.', 'Good. Nothing changes today.'],
  okay: ['Okay. The plan stays as it is.', 'Fine by me. Nothing changes today.'],
  low: ['That is fine. Today gets lighter.', 'Rest counts too. I made today lighter.'],
};
export const replyLine = (mood, date) => pick(REPLIES[mood], date);

export function movedLine(result, minimum) {
  if (result.minutes <= 0) return 'Nothing needed to move.';
  const days = result.dates.map((d) => WEEKDAYS[weekdayOf(d)]);
  const where = days.length > 1 ? `${days.slice(0, -1).join(', ')} and ${days[days.length - 1]}` : days[0];
  return `Kept ${duration(minimum)} today, moved ${duration(result.minutes)} to ${where}.`;
}
